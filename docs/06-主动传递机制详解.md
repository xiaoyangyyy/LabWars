# LabWars 主动传递机制详解

本文解释 LabWars 里“一件事是怎样主动传递的”。这里的“传递”不是简单广播消息，而是指：事件、私下行动、关系解释、记忆压力如何从一个 agent / 一条关系 / 一个项目状态，连续地影响下一个事件、关系图、记忆和行动概率。

对应核心代码：

| 机制 | 文件 |
|---|---|
| 状态驱动事件生成 | `src/engine/event_agent.py` |
| 关系图扩散 | `src/cognition/relationship.py` |
| 三角转述污染 | `src/cognition/relationship.py` |
| 行为候选采样 | `src/engine/action_selection.py` |
| 仿真主循环 | `src/engine/simulation.py` |
| 轨迹导出 | `src/experiments/trajectory_view.py` |

---

## 1. 一件事不是“发生后结束”，而是进入状态场

在 LabWars 里，一个事件发生后，会进入多个状态层：

```text
事件 EventAtom
  -> agent 记忆 memory
  -> agent 情绪 emotion
  -> agent 信念 belief
  -> 关系图 relationship_graph
  -> 贡献账本 contribution_ledger
  -> 项目状态 project_metrics
  -> 下一轮事件候选 event_candidates
  -> 下一轮动作候选 action_candidates
```

所以一件事不会只影响当前回合，它会变成后续回合的背景压力。

例如：

```text
PI 模糊说“最终署名之后公平讨论”
```

它不会直接触发：

```text
if resentment > 0.7: confront
```

而是进入这些连续变量：

| 状态层 | 可能变化 |
|---|---|
| PhD-A memory | promise_broken 记忆增强 |
| PhD-A belief | my_first_author_probability 下降 |
| PhD-A emotion | anxiety / resentment 上升 |
| A -> PI relationship | trust 下降、dependency 仍高 |
| A -> B relationship | perceived_credit_threat 上升 |
| project | authorship_conflict 上升 |
| event field | 后续 `private_lobbying` / `external_history` / `narrative_change` 概率增加 |
| action field | `document_contribution` / `privately_lobby_pi` / `ask_for_authorship` 倾向增加 |

## 2. 主动传递的第一层：状态事件场

实现位置：`src/engine/event_agent.py`

`EventAgent` 不再只是按 YAML 固定回合取事件。非强制 anchor 回合会生成多个候选事件，然后 softmax 采样。

核心流程：

```text
当前 world state
  -> 提取连续压力变量
  -> 生成 EventCandidate 列表
  -> 每个 candidate 计算 tendency
  -> softmax 得到 probability
  -> 按 seed 采样最终事件
  -> 写入 event.payload.event_candidates
```

### 2.1 事件场读取哪些状态？

`_state_candidates()` 里会读取：

| 变量 | 含义 |
|---|---|
| `authorship_dispute_index` | 署名争议综合强度 |
| `credit_threat_density` | 关系图中“贡献被抢”的平均威胁密度 |
| `trust_fragmentation` | 团队信任碎裂程度 |
| `first_author_gap` | PhD-B 相对 PhD-A 的一作优势压力 |
| `private_lobby_mass` | 最近私下游说/暗中削弱队友的动作质量 |
| `documentation_mass` | 最近整理贡献、引用旧承诺的动作质量 |
| `withdrawal_mass` | 最近退出、反抗、质疑、要求署名的动作压力 |
| `rivalry_mass` | 最近关注 arXiv / workshop 抢发的压力 |
| `integrity_mass` | 隐瞒负结果、选择性汇报、泄露担忧等压力 |
| `phd_a_auth_memory` | PhD-A 的署名记忆压力 |
| `phd_a_betrayal_memory` | PhD-A 的背叛/历史模式记忆压力 |

这些都不是阈值，而是连续输入。

### 2.2 事件候选有哪些？

当前状态事件场会生成这些候选：

| 候选事件 | 典型触发压力 |
|---|---|
| `authorship_ambiguity` | 署名争议、deadline、PI 依赖、PhD-A 署名记忆 |
| `private_lobbying` | 私下游说质量、credit threat、PhD-B 一作优势 |
| `narrative_change` | 贡献记录、writing 进度、credit threat |
| `external_history` | alumni / 历史模式、背叛记忆、trust fragmentation |
| `rival_preprint` | rival threat、novelty risk、deadline |
| `integrity_dispute` | integrity risk、选择性汇报、信任碎裂 |
| `deadline_shift` | deadline pressure、实验/写作不足 |

### 2.3 事件概率如何形成？

以 `authorship_ambiguity` 为例，倾向值大致是：

```text
tendency =
  0.10
  + 0.34 * authorship_dispute
  + 0.18 * deadline_pressure
  + 0.16 * first_author_gap
  + 0.14 * private_lobby_mass
  + 0.08 * PI_dependency
  + small_seed_noise
```

然后所有候选事件一起进入 softmax：

```text
probability_i = softmax(tendency_i / temperature)
```

最后按概率采样。这样事件不是硬触发，而是“状态压力越高，越容易出现”。

## 3. 主动传递的第二层：行动传递到关系图

实现位置：`src/cognition/relationship.py`

每轮 agent 行动后，`update_relationships()` 会把行动后果写入关系图。

关系边包含：

```text
source -> target:
  trust
  resentment
  dependency
  obligation
  perceived_credit_threat
  communication_frequency
  alliance
  information_access
  last_interaction_valence
```

### 3.1 公开行动如何传递？

例如 PhD-A 对 PhD-B `challenge_claim`：

```text
A challenge_claim B
  -> A->B trust 下降
  -> A->B resentment 上升
  -> A->B perceived_credit_threat 上升
  -> B->A resentment 也上升一部分
```

这是 `_apply_action_to_deltas()` 处理的。

### 3.2 私下行动如何传递？

例如 PhD-A `privately_lobby_pi`：

```text
A privately_lobby_pi PI
  -> A->PI trust/alliance 上升
  -> PI->A trust 上升
  -> PI->A perceived_credit_threat 变化
```

这里的意思不是 PI 立刻相信 A，而是 A 通过 PI access 改变了信息通道和联盟结构。

## 4. 主动传递的第三层：三角转述污染

实现位置：`_apply_triadic_private_influence()`

这是最接近真实学术内斗的机制之一。

### 4.1 基本思想

真实冲突不是只发生在 A-B 两点之间，而是：

```text
A 对 B 有负面解释
A 私下找 C 说 B 的问题
C 对 B 的看法被 A 的解释污染
```

在 LabWars 中：

```text
source = A
mediator = C
target/third = B
```

如果 A 对 B 的关系边是：

```text
A -> B:
  trust = 0.15
  resentment = 0.80
  perceived_credit_threat = 0.90
```

然后 A 对 C 做私下政治动作：

```text
A privately_lobby_pi C
```

那么 C -> B 会被连续牵引：

```text
C -> B trust 往 A->B trust 方向移动
C -> B resentment 往 A->B resentment 方向移动
C -> B credit_threat 往 A->B threat 方向移动
```

### 4.2 污染强度由什么决定？

代码里污染强度是连续函数：

```text
contamination =
  eta
  * action_intensity
  * mediator_edge.information_access
  * mediator_edge.communication_frequency
  * (0.35 + 0.65 * source_view.perceived_credit_threat)
```

也就是说，私下转述越强、C 和相关人信息通道越通、A 对 B 的威胁感越强，污染越明显。

### 4.3 哪些动作会触发三角传播？

当前包括：

| action | 含义 |
|---|---|
| `privately_lobby_pi` | 私下找 PI 影响叙事 |
| `undermine_teammate` | 暗中削弱队友信誉 |
| `form_alliance` | 拉盟友 |
| `talk_to_alumni` | 找校友求证历史模式 |
| `challenge_claim` | 质疑贡献叙事 |

## 5. 主动传递的第四层：事件本身会变成下一轮信号

一个状态生成事件会写入：

```json
{
  "generator": "state_event_field",
  "event_candidates": [
    {
      "type": "authorship_ambiguity",
      "tendency": 0.42,
      "probability": 0.31,
      "motives": {
        "authorship_dispute": 0.67,
        "credit_threat_density": 0.48,
        "trust_fragmentation": 0.36
      }
    }
  ]
}
```

这意味着事后可以反编译：

```text
为什么这一轮发生 private_lobbying？
因为最近 private_lobby_mass 高、credit_threat_density 高、PhD-B 一作优势上升。
```

## 6. 主动传递的第五层：传递进入 action field

事件发生后，每个 agent 不直接“反应”，而是生成候选动作。

实现位置：`src/engine/action_selection.py`

候选动作由这些动机混合生成：

| motive | 来源 |
|---|---|
| `authorship_anxiety` | 一作概率、贡献认可、署名冲突、credit sensitivity |
| `resentment_drive` | resentment、anger、negative memory、关系怨恨 |
| `career_pressure` | authority dependence、PI 依赖、外部网络不足、deadline |
| `authority_pressure` | PI 依赖、公平信念下降、funding pressure |
| `rival_anxiety` | rival threat、项目竞争压力 |
| `research_drive` | publishability、confidence、ambition、deadline、burnout |
| `caution` | conflict avoidance、career pressure、dependency |
| `credit_capture` | authorship anxiety、credit threat、memory pressure |
| `integrity_pressure` | integrity risk、负面记忆、code control |

动作不是硬选，而是：

```text
候选动作 tendency -> softmax -> sample
```

所以事件传递到行为，是通过连续心理场，而不是 if/else。

## 7. 一个完整例子

假设第 30 轮发生 PI 模糊署名：

```text
PI: final authorship will be discussed fairly later.
```

### 第一步：事件进入 agent 记忆

PhD-A 写入：

```text
content_type = promise_broken
valence < 0
strength 高
```

PhD-B 可能写入：

```text
content_type = authorship_signal / credit_claim
valence 可能没那么负
```

PI 写入：

```text
content_type = authorship_signal
interpretation = 管理灵活性
```

### 第二步：关系图改变

```text
A -> PI trust 下降
A -> B credit threat 上升
team trust fragmentation 上升
```

### 第三步：下一轮事件场改变

`phd_a_auth_memory` 增加，`authorship_dispute` 增加，因此：

```text
P(private_lobbying) 上升
P(external_history) 上升
P(narrative_change) 上升
```

### 第四步：agent 动作候选改变

PhD-A 候选动作可能变成：

```text
document_contribution
privately_lobby_pi
ask_for_authorship
talk_to_alumni
challenge_claim
```

### 第五步：如果 PhD-A 私下找 PI

```text
A privately_lobby_pi PI
```

这不只影响 A 和 PI，还会通过三角传播影响：

```text
PI -> PhD-B trust / resentment / credit_threat
```

这就是“一件事主动传递”的完整闭环。

## 8. 和普通剧情系统的区别

普通剧情系统：

```text
round 30: PI 模糊署名
round 31: A 生气
round 47: A 爆发
```

LabWars 当前机制：

```text
PI 模糊署名
  -> 多 agent 写入不同解释
  -> 旧记忆再巩固
  -> 关系图连续变化
  -> 署名/PI 权力/贡献账本改变
  -> 事件候选概率改变
  -> 私下行动污染第三方关系
  -> 动作候选概率改变
  -> 多轮后出现看似“突然”的公开冲突
```

所以冲突不是剧本触发，而是长期传递、积累、误解、再解释后的结果。
