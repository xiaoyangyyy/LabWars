# LabWars 记忆系统设计详解

本文解释 LabWars 的记忆系统是如何设计的。核心原则是：

> 记忆不是事实，而是 agent 对事件的主观解释；它会衰减、被召回、被排练、被后续事件重新改写，并最终影响行为倾向。

对应核心代码：

| 功能 | 文件 |
|---|---|
| 记忆数据结构、写入、召回、再巩固 | `src/cognition/memory.py` |
| 每轮记忆流程接入 | `src/cognition/pipeline.py` |
| 记忆影响情绪 | `src/cognition/emotion.py` |
| 记忆影响信念 | `src/cognition/belief.py` |
| 记忆影响动作候选 | `src/engine/action_selection.py` |
| 记忆反事实干预 | `src/engine/intervention.py`, `src/engine/causal.py` |
| 轨迹导出 | `src/experiments/trajectory_view.py` |

---

## 1. 设计目标

LabWars 的记忆系统不是聊天记录，也不是事实数据库。它要模拟真实社会冲突里的主观记忆：

| 真实现象 | 系统设计 |
|---|---|
| 同一事件，每个人记得不一样 | 每个 agent 独立写入 `MemoryRecord` |
| 记忆带情绪颜色 | 每条记忆有 `valence` 和 `strength` |
| 记忆不是证据本身 | 每条记忆有 `interpretation` 和 `evidence_quality` |
| 后续事件会改写旧记忆 | `reconsolidate_memories()` |
| 记忆会影响下一次行为 | recall field 进入 action candidate motives |
| 记忆可以被因果干预 | memory delete / insert / strengthen / correct |

---

## 2. 记忆对象长什么样？

实现类：`MemoryRecord`

一条记忆包含：

```json
{
  "memory_id": "M003",
  "owner": "phd_a",
  "round": 30,
  "event_ref": "E030",
  "content_type": "promise_broken",
  "target": "pi",
  "valence": -0.72,
  "strength": 0.81,
  "strength_0": 0.81,
  "decay": 0.03,
  "rehearsal_count": 0.0,
  "evidence_quality": 0.74,
  "interpretation": "PI may be walking back the first-author promise.",
  "behavioral_hooks": ["ask_for_authorship", "confront", "document_contribution"],
  "was_recalled": [],
  "objective_fact_ref": "E030.objective_fact"
}
```

字段解释：

| 字段 | 含义 |
|---|---|
| `memory_id` | agent 内部记忆编号 |
| `owner` | 这条记忆属于哪个 agent |
| `round` | 写入回合 |
| `event_ref` | 来源事件 |
| `content_type` | 记忆类型，如 `promise_broken` / `credit_claim` / `betrayal_signal` |
| `target` | 记忆指向的人或对象 |
| `valence` | 情绪价，负数表示负面解释，正数表示正面解释 |
| `strength` | 当前强度，会衰减/增强 |
| `strength_0` | 初始强度 |
| `decay` | 衰减速率 |
| `rehearsal_count` | 被召回/排练的累计质量 |
| `evidence_quality` | 证据质量，不等于情绪强度 |
| `interpretation` | 主观解释文本 |
| `behavioral_hooks` | 这类记忆容易牵动哪些行为 |
| `was_recalled` | 哪些回合被召回过 |
| `objective_fact_ref` | 指向客观事件事实，但不是记忆本身 |

## 3. 记忆类型如何决定？

事件类型会映射到记忆内容类型：

```python
CONTENT_TYPE_BY_EVENT = {
  "authorship_promise": "authorship_signal",
  "authorship_ambiguity": "authorship_signal",
  "private_lobbying": "betrayal_signal",
  "narrative_change": "betrayal_signal",
  "negative_result_hidden": "integrity_signal",
  "rival_preprint": "rival_threat",
  "external_history": "historical_pattern"
}
```

但有特殊处理：

| event type | 可能写成 |
|---|---|
| `authorship_promise` | `promise_fulfilled` |
| `authorship_ambiguity` | `promise_broken` |
| `authorship_draft` honored | `promise_fulfilled` |
| `authorship_draft` not honored | `promise_broken` |

这很关键：同样是“署名相关事件”，系统会区分它是承诺被兑现，还是承诺被破坏。

---

## 4. 同一事件为什么每个人记得不一样？

核心函数：`compute_valence()`

记忆的情绪价不是事件固定给的，而是：

```text
valence = tanh(
  observed_signal - agent_specific_expectation
)
```

其中：

```text
observed_signal = framing_signal * memory_salience + event_specific_adjustment
agent_specific_expectation = agent 的角色、信念、人格、当前利益位置
```

### 例子：PI 模糊署名

事件：

```text
PI: final authorship will be discussed fairly later.
```

PhD-A：

```text
role_expectation = my_first_author_probability - 0.5 + extra pressure
observed = ambiguous / negative authorship signal
prediction_error = observed - expectation
valence < 0
```

PhD-B：

```text
可能认为实验贡献终于被承认
valence 没有那么负，甚至接近中性
```

PI：

```text
可能记为管理灵活性
valence 负面程度较低
```

所以系统里不是“大家共享同一个事实表”，而是：

```text
共享 event atom，分裂 subjective memory interpretation
```

---

## 5. 记忆强度如何形成？

核心函数：`initial_strength()`

```text
strength_0 = memory_salience * evidence_quality * (1 + abs(valence) * 0.3)
```

含义：

| 因素 | 影响 |
|---|---|
| `memory_salience` | 事件越重要，记忆越强 |
| `evidence_quality` | 证据越可靠，初始强度越高 |
| `abs(valence)` | 情绪越强，不管正负，都更容易留下强记忆 |

这避免了“负面记忆才强”的单一路径；正向承诺、强烈希望也可以形成高强度记忆。

---

## 6. 记忆解释文本如何生成？

核心函数：`_interpretation_via_llm()`

LLM 只负责生成第一人称解释文本：

```text
“我觉得 PI 在回避之前的一作承诺。”
```

但数值部分不是 LLM 随便决定的：

| 数值 | 来源 |
|---|---|
| `valence` | `compute_valence()` |
| `strength` | `initial_strength()` |
| `content_type` | event type + rule |
| `target` | `_infer_target()` |
| `behavioral_hooks` | `BEHAVIORAL_HOOKS` |

也就是说，LLM 写“解释语义”，动力学数值由系统控制。

---

## 7. 记忆如何召回？

核心函数：`recall_memories()`

召回不是 top-k，也不是超过阈值才召回。所有记忆都参与一个 resonance field。

流程：

```text
当前事件 -> context vector
每条旧记忆 -> memory vector
计算 alignment
结合 strength、recency、rehearsal_count
得到 resonance
softmax(resonance) 得到 attention weight
```

### 7.1 context vector

当前事件被编码为：

```text
context = {
  salience,
  framing,
  recency,
  content_type,
  round_norm
}
```

### 7.2 memory vector

每条记忆被编码为：

```text
memory = [
  strength,
  valence,
  recency_kernel(age),
  content_type_hash,
  target_hash
]
```

### 7.3 resonance

每条记忆的共振强度：

```text
resonance =
  memory.strength
  * recency_kernel(age)
  * (0.35 + 0.65 * alignment)
  * binding
```

其中：

```text
binding = 1 + 0.25 * log1p(rehearsal_count)
```

被反复想起的记忆更容易再次被想起。

### 7.4 情绪会改变召回温度

```text
effective_temp = base_temp * (1 - 0.35 * sigmoid(arousal - 0.4))
```

arousal 越高，softmax 越尖锐，agent 越容易被少数高强度记忆“抓住”。

---

## 8. recall field 是什么？

召回结果不是只返回“哪些记忆被召回”，还形成一个整体记忆场：

```python
RecallResult(
  attention_weights={"M001": 0.42, "M002": 0.21, ...},
  recalled_ids=["M001", "M002", ...],
  recall_field_valence=-0.36,
  recall_field_strength=0.62,
  audit={...}
)
```

### 8.1 recall_field_valence

```text
field_valence = sum(attention_i * memory_i.valence)
```

代表当前被激活记忆整体偏正还是偏负。

### 8.2 recall_field_strength

```text
field_strength = sum(attention_i * memory_i.strength)
```

代表当前记忆场有多强。

### 8.3 audit

每次召回会记录：

```json
{
  "round": 31,
  "agent": "phd_a",
  "recalled_memories": ["M001", "M003"],
  "attention_weights": {"M001": 0.43, "M003": 0.31},
  "recall_field_valence": -0.52,
  "recall_field_strength": 0.67,
  "recall_reason": {
    "M001": "resonance=0.2411, weight=0.4300, content=promise_broken, target=pi"
  },
  "temperature": 0.26
}
```

这用于后续反编译：为什么 agent 这一轮会这么想、这么做。

---

## 9. 记忆如何被排练？

核心函数：`apply_rehearsal()`

每次召回后，记忆会按 attention weight 增加排练次数：

```text
rehearsal_count += attention_weight
```

并记录：

```text
was_recalled.append(current_round)
```

这表示 agent 并不是“想起/没想起”二元状态，而是每条记忆都可能被不同程度地排练。

---

## 10. 记忆如何衰减？

核心函数：`decay_memories()`

记忆每轮会衰减，但情绪 arousal 会降低衰减速度：

```text
effective_decay = decay * (1 - 0.45 * emotional_binding)
```

其中：

```text
emotional_binding = sigmoid(anger + resentment)
```

如果 agent 很愤怒/怨恨，相关记忆会更难淡化。

同时，排练会增强记忆：

```text
rehearsal_boost = 0.08 * log1p(rehearsal_count)
```

所以：

```text
反复想起 -> 更不容易忘 -> 更容易再次想起
```

这形成了长期内斗中常见的“记忆回路”。

---

## 11. 记忆如何被再巩固？

核心函数：`reconsolidate_memories()`

这是目前记忆系统最重要的部分。

真实记忆不是写入后固定不变。后续事件会改变你对旧事件的解释。

流程：

```text
当前事件 + recall attention
  -> 计算当前事件 valence
  -> 对每条被注意到的旧记忆计算 plasticity
  -> 旧记忆 valence 向当前事件 valence 移动
  -> 旧记忆 strength 可能增强
  -> 写入 reconsolidation_history
```

### 11.1 plasticity 由什么决定？

```text
plasticity =
  attention
  * (0.25 + 0.45 * event.memory_salience)
  * (0.45 + 0.35 * emotional_gain + 0.20 * (1 - evidence_quality))
  * (0.50 + 0.30 * same_target + 0.20 * same_content)
```

| 因素 | 含义 |
|---|---|
| `attention` | 旧记忆这轮被多强地激活 |
| `event.memory_salience` | 当前事件有多重要 |
| `emotional_gain` | 当前情绪唤醒程度 |
| `1 - evidence_quality` | 原记忆证据越弱，越容易被改写 |
| `same_target` | 当前事件是否涉及同一对象 |
| `same_content` | 当前事件是否同一类内容 |

### 11.2 valence 如何改写？

```text
new_valence = old_valence + plasticity * (event_valence - old_valence)
```

也就是旧记忆被当前事件往新解释方向拉。

### 11.3 strength 如何改写？

```text
new_strength = old_strength + plasticity * event_salience * (0.35 + abs(event_valence))
```

越强烈的后续事件，越会增强旧记忆。

### 11.4 audit 记录

```json
{
  "round": 35,
  "event_ref": "E035",
  "attention": 0.41,
  "plasticity": 0.13,
  "valence_before": -0.42,
  "valence_after": -0.51,
  "strength_after": 0.73
}
```

这表示第 35 轮事件重新解释了更早的记忆。

## 12. 记忆如何影响行为？

实现位置：`src/engine/action_selection.py`

`RecallResult` 会进入动作候选生成。

首先提取记忆特征：

```text
negative_memory = clamp(-recall_field_valence * recall_field_strength)
positive_memory = clamp(recall_field_valence * recall_field_strength)
memory_pressure = clamp(abs(recall_field_valence) * recall_field_strength)
```

这些进入动机：

| 动机 | 记忆影响 |
|---|---|
| `resentment_drive` | negative_memory 增强怨恨驱动 |
| `credit_capture` | memory_pressure 增强保护贡献的倾向 |
| `integrity_pressure` | negative_memory 增强诚信风险感 |
| `caution` | 通过 career pressure / dependency 间接影响 |

然后动作 tendency 由多个动机加权：

```text
document_contribution = f(credit_capture, authorship_anxiety, caution, integrity_pressure)
confront = f(resentment_drive, authorship_anxiety, authority_pressure, -caution)
privately_lobby_pi = f(authorship_anxiety, career_pressure, caution, credit_capture)
```

最终 softmax 采样。

所以记忆不会直接说：

```text
if memory == betrayal: confront
```

而是改变行为概率场。

---

## 13. 记忆如何影响事件？

实现位置：`src/engine/event_agent.py`

事件场会读取记忆压力：

```text
phd_a_auth_memory = memory_pressure(phd_a, authorship-related types)
phd_a_betrayal_memory = memory_pressure(phd_a, betrayal/history types)
```

这些会提高：

| memory pressure | 影响事件 |
|---|---|
| authorship memory pressure | `authorship_ambiguity` 概率上升 |
| betrayal/history memory pressure | `external_history` 概率上升 |
| private lobbying mass + memory pressure | `private_lobbying` / `narrative_change` 更容易出现 |

也就是说，记忆不只是影响 agent 行为，也会影响“世界下一步发生什么”。

---

## 14. 记忆如何进入因果实验？

LabWars 支持记忆干预：

| 干预 | 含义 |
|---|---|
| `memory_insert` | 插入某条记忆 |
| `memory_delete_pi_promise` | 删除 PI 承诺相关记忆 |
| `memory_strengthen_betrayal` | 强化背叛记忆 |
| `memory_correct_false_rumor` | 纠正假传闻 |

然后通过 causal runner 比较：

```text
control: 正常记忆
treatment: 删除/插入/强化/纠正记忆
outcome: protest_authorship / authorship_escalation_score
```

这可以回答：

```text
如果 PhD-A 没有那条 PI 承诺记忆，后续是否还会爆发？
如果 alumni 历史提醒没发生，署名冲突是否更弱？
```

## 15. 一个完整记忆生命周期例子

### Round 3: PI 暗示 PhD-A 可以 lead paper

PhD-A 写入：

```text
content_type = promise_fulfilled
valence > 0
strength 高
interpretation = PI implied I should lead the paper
```

### Round 30: PI 模糊说之后公平讨论

PhD-A 写入新记忆：

```text
content_type = promise_broken
valence < 0
```

同时旧的 Round 3 记忆被再巩固：

```text
old valence: +0.62
new valence: +0.41 或更低
interpretation_bias 往负方向移动
strength 增强
```

含义：PhD-A 不是简单新增“PI 模糊”记忆，而是开始重新理解 Round 3 的承诺。

### Round 35: alumni 提醒 PI 过去也 deadline 前改署名

PhD-A 的旧记忆再次被改写：

```text
Round 3 承诺记忆 -> 更像“PI 当时就在留后路”
Round 30 模糊记忆 -> 更像“模式重复”
```

### Round 47: PhD-A 威胁退出投稿

这不是突然爆发，而是：

```text
旧承诺记忆
+ 模糊署名记忆
+ alumni 历史模式
+ contribution threat
+ PI dependence
+ career pressure
+ relationship resentment
```

共同改变动作候选概率，最终采样出高强度行动。

## 16. 记忆系统和“真实感”的关系

没有这个记忆系统，仿真会像：

```text
Round 30: resentment +0.2
Round 47: if resentment > 0.7 then protest
```

有这个系统后，仿真变成：

```text
Round 3 的承诺记忆在 Round 30 被改写
Round 30 的模糊记忆在 Round 35 被历史模式强化
这些记忆在 Round 41 被实验失败重新激活
记忆场提高 credit_capture / resentment_drive
但 career_pressure 和 authority_dependency 又压制公开对抗
最后行为从多个候选动作中采样出现
```

这就是“长期压抑后的行为”，而不是“数值过线后的动作”。

## 17. 当前记忆系统的可观察输出

你可以从日志或 trajectory viewer 看到：

| 输出 | 位置 |
|---|---|
| `memory_written` | 每轮 agent_deltas |
| `recall_audit` | 每轮 agent_deltas |
| `memory_reconsolidation` | 每轮 agent_deltas / trajectory view |
| `attention_weights` | recall audit |
| `recall_field_valence` | recall audit |
| `recall_field_strength` | recall audit |
| `reconsolidation_history` | memory object 内部 |
| `private_motives` | action log |
| `event_candidates` | event payload |

这使得每个行为都可以被反编译：

```text
这个 action 是由哪些记忆、哪些关系压力、哪些 PI 权力面、哪些署名压力共同推出来的？
```

---

## 18. 一句话总结

LabWars 的记忆系统不是记录“发生了什么”，而是模拟“每个 agent 如何解释发生了什么，并且这种解释如何在后续事件中被召回、强化、污染、改写，最后影响行为和世界事件”。
